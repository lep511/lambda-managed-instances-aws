By default, Lambda encrypts the EBS volumes attached to managed instances using an AWS-managed key. For workloads with stricter compliance requirements, a customer-managed AWS Key Management Service (KMS) key gives you control over rotation policies, cross-account access, and the audit trail in CloudTrail.

This page uses the `$KMS_KEY_ARN`, `$SUBNET_IDS`, `$SECURITY_GROUP_ID`, `$OPERATOR_ROLE_ARN`, and `$EXECUTION_ROLE_ARN` environment variables from [Module 1](https://catalog.us-east-1.prod.workshops.aws/event/dashboard/en-US/workshop/when-to-use-lmi/create-capacity-provider). If your terminal session was reset, re-export them with the commands below.

```bash
export KMS_KEY_ARN=$(aws kms describe-key \
  --key-id alias/lmi-workshop-ebs-key \
  --query "KeyMetadata.Arn" --output text)

export SUBNET_IDS=$(aws ec2 describe-subnets \
  --filters "Name=tag:Name,Values=lmi-workshop-private-*" \
  --query "Subnets[*].SubnetId" --output text | tr '\t' ',')

export SECURITY_GROUP_ID=$(aws ec2 describe-security-groups \
  --filters "Name=tag:Name,Values=lmi-workshop-sg" \
  --query "SecurityGroups[0].GroupId" --output text)

export OPERATOR_ROLE_ARN=$(aws iam get-role \
  --role-name LMIWorkshopOperatorRole \
  --query "Role.Arn" --output text)

export EXECUTION_ROLE_ARN=$(aws iam get-role \
  --role-name LMIWorkshopExecutionRole \
  --query "Role.Arn" --output text)
```

The sample outputs shown on this page were captured during workshop testing. Your instance IDs and key ARNs will differ.

In this step you will:

1. Verify the pre-provisioned KMS key and its policy
2. Create a new capacity provider that encrypts its instances with the key
3. Deploy a function and verify the EBS volumes use your CMK

Key things to understand:

- Encryption is set at **capacity provider creation time** and cannot be changed later
- The operator role needs `kms:CreateGrant` because EBS uses grants for volume encryption
- Not all volumes on a managed instance may be encrypted with your CMK (Lambda attaches operational volumes separately)

## Verify the pre-provisioned KMS key

A customer-managed KMS key (`alias/lmi-workshop-ebs-key`) was created as part of the workshop infrastructure. The key policy already grants your operator role the required encryption permissions including `kms:CreateGrant`.

Confirm the key is available:

```bash
echo "KMS Key ARN: $KMS_KEY_ARN"

aws kms describe-key \
  --key-id alias/lmi-workshop-ebs-key \
  --query "KeyMetadata.[KeyId,KeyState,Description]" \
  --output table
```

You should see the key in `Enabled` state:

```
-----------------------------------------------------------------
|                          DescribeKey                          |
+---------------------------------------------------------------+
|  f5702009-d6b8-4bac-8044-ba507b0655df                         |
|  Enabled                                                      |
|  Customer-managed key for LMI workshop EBS volume encryption  |
+---------------------------------------------------------------+
```

The key policy grants the operator role (`LMIWorkshopOperatorRole`) the actions Lambda needs to encrypt EBS volumes: `kms:Encrypt`, `kms:Decrypt`, `kms:GenerateDataKey*`, `kms:DescribeKey`, and `kms:CreateGrant`. The `CreateGrant` permission is critical because EBS uses KMS grants (not direct API calls) to authorize volume-encryption operations when Lambda launches instances.

## Create an encrypted capacity provider

Attach the KMS key to a new capacity provider. Existing capacity providers cannot be re-keyed, so a new provider is required:

```bash
aws lambda create-capacity-provider \
  --capacity-provider-name lmi-workshop-encrypted-cp \
  --vpc-config "SubnetIds=[$SUBNET_IDS],SecurityGroupIds=[$SECURITY_GROUP_ID]" \
  --permissions-config "CapacityProviderOperatorRoleArn=$OPERATOR_ROLE_ARN" \
  --instance-requirements "Architectures=[x86_64]" \
  --capacity-provider-scaling-config "MaxVCpuCount=16" \
  --kms-key-arn $KMS_KEY_ARN
```

The command returns JSON with `"State": "Pending"` and your KMS key ARN in the `KmsKeyArn` field:

```json
{
    "CapacityProvider": {
        "CapacityProviderArn": "arn:aws:lambda:us-east-1:123456789012:capacity-provider:lmi-workshop-encrypted-cp",
        "State": "Pending",
        "KmsKeyArn": "arn:aws:kms:us-east-1:123456789012:key/f5702009-...",
        "CapacityProviderScalingConfig": {
            "MaxVCpuCount": 16,
            "ScalingMode": "Auto"
        }
    }
}
```

The provider transitions to Active within 30-60 seconds.

Verify the provider is active and shows the KMS key:

```bash
aws lambda get-capacity-provider \
  --capacity-provider-name lmi-workshop-encrypted-cp \
  --query "CapacityProvider.[State,KmsKeyArn]" \
  --output table
```

```
---------------------------------------------------------------------------------
|                              GetCapacityProvider                              |
+-------------------------------------------------------------------------------+
|  Active                                                                       |
|  arn:aws:kms:us-east-1:123456789012:key/f5702009-...                          |
+-------------------------------------------------------------------------------+
```

## Verify EBS volumes are encrypted

Deploy a function to the encrypted provider. This reuses the `function.zip` file created in Module 1 ([Deploy Your First Function](https://catalog.us-east-1.prod.workshops.aws/event/dashboard/en-US/workshop/when-to-use-lmi/deploy-first-function)).

Create the function zip if you don't have it from Module 1:

```bash
mkdir -p ./function
cat > ./function/lambda_function.py << 'EOF'
import json
import time

def lambda_handler(event, context):
    count = event.get("count", 1000)
    start = time.time()
    primes = []
    for num in range(2, count):
        is_prime = True
        for i in range(2, int(num**0.5) + 1):
            if num % i == 0:
                is_prime = False
                break
        if is_prime:
            primes.append(num)
    duration = time.time() - start
    return {"statusCode": 200, "body": json.dumps({"message": "Hello from the encrypted capacity provider!", "primes_found": len(primes), "duration_seconds": round(duration, 3), "request_id": context.aws_request_id})}
EOF
cd ./function && zip function.zip lambda_function.py && cd ..
```

```bash
export ENCRYPTED_CP_ARN=$(aws lambda get-capacity-provider \
  --capacity-provider-name lmi-workshop-encrypted-cp \
  --query "CapacityProvider.CapacityProviderArn" \
  --output text)

aws lambda create-function \
  --function-name lmi-workshop-encrypted-function \
  --runtime python3.14 \
  --handler lambda_function.lambda_handler \
  --zip-file fileb://function/function.zip \
  --role "$EXECUTION_ROLE_ARN" \
  --memory-size 2048 \
  --capacity-provider-config "LambdaManagedInstancesCapacityProviderConfig={CapacityProviderArn=$ENCRYPTED_CP_ARN,ExecutionEnvironmentMemoryGiBPerVCpu=2.0}"

aws lambda publish-version \
  --function-name lmi-workshop-encrypted-function

echo "Waiting for encrypted function to become Active..."
while [ "$(aws lambda get-function --function-name lmi-workshop-encrypted-function:1 --query 'Configuration.State' --output text)" != "Active" ]; do
  echo "  Still provisioning... ($(date +%H:%M:%S))"
  sleep 15
done
echo "Function is Active!"
```

This wait takes 2-5 minutes as Lambda provisions new instances with encrypted EBS volumes.

Once active, inspect the volumes attached to the encrypted instances. The `--include-managed-resources` flag (requires AWS CLI v2) makes Lambda-managed instances visible:

EC2 instances may take 1-2 minutes to appear after the function becomes active. If the command below returns empty results, wait 30-60 seconds and retry. Instances need time to launch and receive their capacity provider tags.

```bash
INSTANCE_IDS=$(aws ec2 describe-instances \
  --include-managed-resources \
  --filters "Name=tag:aws:lambda:capacity-provider,Values=*lmi-workshop-encrypted-cp" \
            "Name=instance-state-name,Values=running" \
  --query "Reservations[*].Instances[*].InstanceId" \
  --output text)

for INSTANCE_ID in $INSTANCE_IDS; do
  echo "Instance: $INSTANCE_ID"
  aws ec2 describe-volumes \
    --include-managed-resources \
    --filters "Name=attachment.instance-id,Values=$INSTANCE_ID" \
    --query "Volumes[*].[VolumeId,Encrypted,KmsKeyId]" \
    --output table
done
```

You will see two volumes per instance: one unencrypted operational volume managed by Lambda for internal use, and one encrypted data volume using your CMK. Both are expected.

```
Instance: i-029e8f15f585b2b8a
+-----------------------+--------+--------------------------------------------------------------------------------+
|  vol-09be060233b6463c3|  True  |  arn:aws:kms:us-east-1:123456789012:key/f5702009-...                            |
|  vol-079335a82dfa4a041|  False |  None                                                                          |
+-----------------------+--------+--------------------------------------------------------------------------------+
```

Each instance shows two volumes: one encrypted with your CMK (`True` + key ARN) and one unencrypted operational volume (`False` + None). The encrypted volume is your function's data volume, protected by your customer-managed KMS key.

The KMS key is locked in at capacity-provider creation time. To change keys later, create a new capacity provider and migrate your functions to it.
