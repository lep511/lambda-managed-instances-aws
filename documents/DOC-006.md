Standard Lambda gives you isolation for free. Every execution environment runs in its own [Firecracker microVM](https://firecracker-microvm.github.io/) (a lightweight virtual machine), and workloads on the same function never see each other. Lambda Managed Instances is different. Functions sharing a capacity provider run in containers on the same EC2 instances, and containers do not provide strong workload isolation. **The capacity provider itself is the security boundary.**

That single fact drives every multi-tenancy and security decision in LMI. This module walks through workload grouping strategies, hands-on deployment of isolated capacity providers, KMS encryption for EBS volumes, compliance patterns, and enterprise governance controls.

This is an optional module. If you are running short on time, skip ahead to the [Conclusion](https://catalog.us-east-1.prod.workshops.aws/event/dashboard/en-US/workshop/conclusion) and [Cleanup](https://catalog.us-east-1.prod.workshops.aws/event/dashboard/en-US/workshop/cleanup).

## What you will accomplish

1. Understand why the capacity provider is the security boundary
2. Evaluate three workload grouping strategies (shared, isolated, hybrid)
3. Deploy a second capacity provider and verify isolation
4. Configure KMS encryption for EBS volumes on managed instances
5. Verify IMDSv2 enforcement and review compliance scanner findings
6. Apply enterprise governance patterns (SCPs, naming conventions, access control)

## Key concepts

| Concept | Description |
| --- | --- |
| Security boundary | The capacity provider, not the container, provides isolation between workloads |
| Shared provider | Multiple functions on one provider: better utilization, lower cost, no cross-workload isolation |
| Isolated provider | One provider per tenant or trust level: strong isolation, higher baseline cost |
| `lambda:PassCapacityProvider` | IAM action that gates which users can assign functions to which providers |
| KMS encryption | Customer-managed key for EBS volumes on managed instances |
| IMDSv2 | Instance metadata security enforced by default on all managed instances |

Containers within a capacity provider do NOT provide security isolation. Never place mutually untrusted workloads on the same capacity provider.
