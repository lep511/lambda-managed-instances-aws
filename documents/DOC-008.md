Create a second capacity provider, deploy a function to it, and prove that the two providers run on completely separate EC2 instances. This step makes the "capacity provider = security boundary" idea concrete rather than theoretical.

This page uses the `$SUBNET_IDS`, `$SECURITY_GROUP_ID`, `$OPERATOR_ROLE_ARN`, `$EXECUTION_ROLE_ARN`, and `$LMI_VERSION` environment variables set in [Module 1](https://catalog.us-east-1.prod.workshops.aws/event/dashboard/en-US/workshop/when-to-use-lmi/create-capacity-provider). If your terminal session was reset, re-export the resource variables with the commands below, then set `LMI_VERSION` to your published version number, for example `export LMI_VERSION=1`.

```bash
export SUBNET_IDS=$(aws ec2 describe-subnets \
  --filters "Name=tag:Name,Values=lmi-workshop-private-*" \
  --query "Subnets[*].SubnetId" --output text | tr '\t' ',')

export SECURITY_GROUP_ID=$(aws ec2 describe-security-groups \
  --filters "Name=tag:Name,Values=lmi-workshop-sg" \
  --query "SecurityGroups[0].GroupId" --output text)

export OPERATOR_ROLE_ARN=$(aws iam get-role \
  --role-name LMIWorkshopOperatorRole \
  --query "Role.Arn" --output text)

export EXECUTION_ROLE_ARN=$(aws iam get-role \
  --role-name LMIWorkshopExecutionRole \
  --query "Role.Arn" --output text)
```

Timing values in the isolation demo below were captured during testing. Your exact durations will differ, but the pattern (Tenant B unaffected by Tenant A load) should be consistent.

In this step you will:

1. Create a second capacity provider for "Tenant B"
2. Deploy a function attached to the new provider
3. Verify the two providers run on completely separate EC2 instances
4. Prove that load on Tenant A has zero impact on Tenant B response times
5. Understand the cost tradeoff of isolation (double the instance floor)

## Create a second capacity provider

Represent "Tenant B" with a new capacity provider. It uses the same VPC as the existing `lmi-workshop-capacity-provider` but sits in its own security boundary with its own instance fleet:

```bash
aws lambda create-capacity-provider \
  --capacity-provider-name lmi-workshop-tenant-b-cp \
  --vpc-config "SubnetIds=[$SUBNET_IDS],SecurityGroupIds=[$SECURITY_GROUP_ID]" \
  --permissions-config "CapacityProviderOperatorRoleArn=$OPERATOR_ROLE_ARN" \
  --instance-requirements "Architectures=[x86_64]" \
  --capacity-provider-scaling-config "MaxVCpuCount=16" \
  --tags Tenant=tenant-b,Environment=workshop
```

The command returns JSON showing the new provider in `Creating` state:

```json
{
    "CapacityProvider": {
        "CapacityProviderArn": "arn:aws:lambda:us-east-1:123456789012:capacity-provider:lmi-workshop-tenant-b-cp",
        "State": "Creating",
        "CapacityProviderScalingConfig": {
            "MaxVCpuCount": 16,
            "ScalingMode": "Auto"
        }
    }
}
```

Wait for the provider to transition to `Active`:

```bash
aws lambda get-capacity-provider \
  --capacity-provider-name lmi-workshop-tenant-b-cp \
  --query "CapacityProvider.State" \
  --output text
```

## Deploy a function on Tenant B

Create the function zip if you don't have it from Module 1:

```bash
mkdir -p ./function
cat > ./function/lambda_function.py << 'EOF'
import json
import time

def lambda_handler(event, context):
    count = event.get("count", 1000)
    start = time.time()
    primes = []
    for num in range(2, count):
        is_prime = True
        for i in range(2, int(num**0.5) + 1):
            if num % i == 0:
                is_prime = False
                break
        if is_prime:
            primes.append(num)
    duration = time.time() - start
    return {"statusCode": 200, "body": json.dumps({"message": "Hello from Tenant B!", "primes_found": len(primes), "duration_seconds": round(duration, 3), "request_id": context.aws_request_id})}
EOF
cd ./function && zip function.zip lambda_function.py && cd ..
```

Attach the function to the Tenant B provider:

```bash
export TENANT_B_CP_ARN=$(aws lambda get-capacity-provider \
  --capacity-provider-name lmi-workshop-tenant-b-cp \
  --query "CapacityProvider.CapacityProviderArn" \
  --output text)

aws lambda create-function \
  --function-name lmi-workshop-tenant-b-function \
  --runtime python3.14 \
  --handler lambda_function.lambda_handler \
  --zip-file fileb://function/function.zip \
  --role "$EXECUTION_ROLE_ARN" \
  --memory-size 2048 \
  --capacity-provider-config "LambdaManagedInstancesCapacityProviderConfig={CapacityProviderArn=$TENANT_B_CP_ARN,ExecutionEnvironmentMemoryGiBPerVCpu=2.0}"
```

The response shows the function in `Pending` state with its ARN and capacity provider configuration:

```json
{
    "FunctionName": "lmi-workshop-tenant-b-function",
    "FunctionArn": "arn:aws:lambda:us-east-1:123456789012:function:lmi-workshop-tenant-b-function",
    "Runtime": "python3.14",
    "State": "Pending",
    "MemorySize": 2048
}
```

Publish and wait for it to become active:

```bash
TENANT_B_VERSION=$(aws lambda publish-version \
  --function-name lmi-workshop-tenant-b-function \
  --description "Tenant B initial deployment" \
  --query "Version" --output text)

echo "Published version: $TENANT_B_VERSION"

echo "Waiting for tenant-b function to become Active..."
while [ "$(aws lambda get-function --function-name lmi-workshop-tenant-b-function:$TENANT_B_VERSION --query 'Configuration.State' --output text)" != "Active" ]; do
  echo "  Still provisioning... ($(date +%H:%M:%S))"
  sleep 15
done
echo "Function is Active!"
```

This wait takes 2-5 minutes as Lambda provisions new instances for the second capacity provider.

## Verify the two providers run on separate instances

List the instances for each provider side by side:

```bash
echo "=== Tenant A instances (lmi-workshop-capacity-provider) ==="
aws ec2 describe-instances \
  --include-managed-resources \
  --filters "Name=tag:aws:lambda:capacity-provider,Values=*lmi-workshop-capacity-provider" \
            "Name=instance-state-name,Values=running" \
  --query "Reservations[*].Instances[*].[InstanceId,InstanceType]" \
  --output table

echo ""
echo "=== Tenant B instances (lmi-workshop-tenant-b-cp) ==="
aws ec2 describe-instances \
  --include-managed-resources \
  --filters "Name=tag:aws:lambda:capacity-provider,Values=*lmi-workshop-tenant-b-cp" \
            "Name=instance-state-name,Values=running" \
  --query "Reservations[*].Instances[*].[InstanceId,InstanceType]" \
  --output table
```

You should see two completely separate sets of instances. No instance appears in both lists.

## Demonstrate noisy-neighbor isolation

The load test uses the `lmi-workshop-load-test` function, which was deployed by the team stack during [Getting Started](https://catalog.us-east-1.prod.workshops.aws/event/dashboard/en-US/workshop/getting-started). Verify it exists:

```bash
aws lambda get-function --function-name lmi-workshop-load-test --query "Configuration.FunctionName" --output text
```

You should see `lmi-workshop-load-test`. If the function is not found, return to [Getting Started](https://catalog.us-east-1.prod.workshops.aws/event/dashboard/en-US/workshop/getting-started) and verify the team stack deployed successfully.

First, invoke Tenant B to get a baseline response time:

```bash
echo "=== Tenant B baseline (no load) ==="
aws lambda invoke \
  --function-name lmi-workshop-tenant-b-function:$TENANT_B_VERSION \
  --payload '{"count": 5000}' \
  --cli-binary-format raw-in-base64-out ./tenant-b-baseline.json
cat ./tenant-b-baseline.json | python3 -c "import sys,json; d=json.load(sys.stdin); print('Duration:', json.loads(d['body'])['duration_seconds'], 'seconds')"
```

Now saturate Tenant A with 50 concurrent requests in the background, and invoke Tenant B while that load is in flight:

```bash
echo "=== Saturating Tenant A with 50 concurrent requests (background) ==="
aws lambda invoke --function-name lmi-workshop-load-test \
  --payload '{"target_function": "lmi-workshop-function:'$LMI_VERSION'", "concurrency": 50, "payload": {"count": 500000}}' \
  --cli-binary-format raw-in-base64-out ./tenant-a-load.json >/dev/null 2>&1 &
LOAD_PID=$!

# Give the load a few seconds to ramp up and saturate Tenant A's environments
sleep 5

echo ""
echo "=== Invoking Tenant B while Tenant A is under load ==="
aws lambda invoke \
  --function-name lmi-workshop-tenant-b-function:$TENANT_B_VERSION \
  --payload '{"count": 5000}' \
  --cli-binary-format raw-in-base64-out ./tenant-b-result.json
cat ./tenant-b-result.json | python3 -c "import sys,json; d=json.load(sys.stdin); print('Duration:', json.loads(d['body'])['duration_seconds'], 'seconds')"

# Wait for the background Tenant A load to finish
wait $LOAD_PID

echo ""
echo "=== Tenant A load test result ==="
cat ./tenant-a-load.json | python3 -m json.tool
```

The load test targets `lmi-workshop-function:$LMI_VERSION`. If the variable is empty, set it with `export LMI_VERSION=<your version>`.

Tenant B responds in under 1-2 ms regardless of Tenant A's load. The two providers share the VPC and the operator role but nothing else at runtime: separate EC2 instances, separate execution environments, separate concurrency budgets.

Example output:

```
=== Tenant B baseline (no load) ===
Duration: 0.001 seconds

=== Invoking Tenant B while Tenant A is under load ===
Duration: 0.001 seconds
```

Tenant B's response time is identical whether Tenant A is idle or fully saturated.

If both functions were on the same capacity provider, Tenant A's 50 concurrent requests could saturate the shared environments and Tenant B would see throttling or elevated latency. Isolation eliminates this noisy-neighbor risk.

## The cost of isolation

Isolation isn't free. Every new capacity provider adds a three-instance floor:

| Approach | Instances at rest | Approximate monthly cost |
| --- | --- | --- |
| Shared (one provider, both functions) | 3 minimum | ~$150 |
| Isolated (one provider per tenant) | 6 minimum | ~$300 |

This comparison assumes both scenarios start from the 3-instance floor. If you completed Module 2, your `lmi-workshop-capacity-provider` may already be running more than 3 instances from the scaling exercises there. The doubling relationship still holds, but your actual baseline cost will be higher than the shared-provider row shown above.

Double the isolation, double the baseline. This is the tradeoff behind every multi-tenancy decision in LMI: how much cross-workload isolation do you actually need, and how much are you willing to pay to get it.

Beyond cost, capacity also plays a role. Each capacity provider supports a maximum of 100 published function versions. A shared provider serving many microservices with frequent deploys can hit this limit, forcing you to isolate whether or not security requires it.
